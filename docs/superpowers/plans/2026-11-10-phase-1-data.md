# Phase 1 · Data Ingestion, First Stream and Streamlit UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Download a sample month of every source, ingest it with Spark into Parquet, build the hourly feature table, run a first Structured Streaming job (live capture or replay), and show all of it in a Streamlit UI from day one.

**Architecture:** Thin download/capture scripts only fetch and convert formats into `data/raw` and `data/stream/landing`. Spark modules (one per source) parse with explicit schemas, convert to UTC and write Parquet; `features.py` holds streaming-safe transformations shared by batch and streaming. A `views.py` layer aggregates in Spark and returns small pandas frames to a Streamlit app with four tabs (Data status, History, Live, Analysis).

**Tech Stack:** Python 3.13, PySpark 4.2.x (DataFrame API, Structured Streaming, `pyspark.ml.stat`), pandas < 3 (plotting only), requests, openpyxl, Streamlit (with its bundled Altair), pytest, ruff, uv.

**Spec:** `docs/plan.md` and `AGENTS.md` (decisions, data-source facts, Spark rules, Python guide, tests).

## Global Constraints

- Everything in the repository is in English: identifiers, docstrings (PEP 257), comments, logs, column names, docs, UI and chart labels.
- All timestamps are UTC (`spark.sql.session.timeZone=UTC`); calendar features (local hour, local date, day of week, month, holiday) are derived from `Europe/Madrid` wall time.
- Aggregation of power (MW) and prices is by mean, never by sum.
- Explicit schemas when reading raw data; never `inferSchema` in pipeline code.
- Processing in Spark only. Outside Spark: fetching, format conversion (JSONP stays text for Spark; XLSX → CSV), and `toPandas()` on small results already aggregated in Spark.
- Python UDFs only when no native function exists (none are expected in this phase).
- Tests never use the network; real responses are stored trimmed in `tests/fixtures/`.
- `data/` is never versioned. Bulk downloads (the full 2021–2026 history) only with the team's permission; this phase works with the sample month **January 2025** (plus the MIBGAS 2025 file).
- Never run `git commit`/`git push` unless the team asks in that same message; each task ends with a checkpoint and a proposed commit message.
- Dependencies through `uv add`; `pandas` stays `<3`.

## Review Focus

1. REE real-time stalls (as on 2026-11-03): capture must keep polling and log a warning on HTTP errors or empty payloads, and the Live tab must show the age of the last reading and a warning when it is older than 20 minutes. Tests in Task 10 and Task 11.
2. An interrupted download must leave no partial file that looks complete: writes go to a `.part` file and are renamed; a rerun skips complete files. Test in Task 2.
3. A fresh clone with an empty `data/` must open the UI with "no data yet" messages, not exceptions. Tests in Task 11.
4. REData answers HTTP 400 or a JSON `errors` body ("no disponibles en este momento"): retry with backoff, then record the job as failed and continue with the next one. Test in Task 2.
5. Today's (and yesterday's) files are incomplete when downloaded: files whose period ends on or after yesterday are always re-fetched instead of skipped. Test in Task 2.

### Task 2: Resumable downloader

**Files:**

- Create: `src/spain_electricity/download.py`, `tests/unit/test_download.py`

**Interfaces:**

- Produces:
  - `@dataclass(frozen=True) class DownloadJob: url: str; destination: Path; covers_until: date; validator: Callable[[bytes], bool] | None = None`.
  - `@dataclass class DownloadReport: fetched: int = 0; skipped: int = 0; failed: list[str] = field(default_factory=list)`.
  - `class DownloadError(Exception)`.
  - `should_fetch(destination: Path, covers_until: date, today: date) -> bool`: True if the file is missing or `covers_until >= today - timedelta(days=1)`.
  - `fetch(url: str, destination: Path, *, session: requests.Session, validator=None, retries: int = 3, backoff_seconds: float = 2.0, timeout: float = 60.0, sleep=time.sleep) -> None`: writes `destination.name + ".part"` in the same folder, renames with `os.replace` on success; retries on HTTP status ≥ 400, request exceptions or a failing validator; raises `DownloadError` after the last attempt and leaves no `.part` file.
  - `download_all(jobs: Iterable[DownloadJob], *, session: requests.Session | None = None, pause_seconds: float = 1.0, today: date | None = None, sleep=time.sleep) -> DownloadReport`: logs one line per job; a failed job is appended to `report.failed` (its URL) and the loop continues.

**Files:**

- Create: `src/spain_electricity/capture.py`, `src/spain_electricity/streaming.py`, `scripts/capture_realtime.py`, `scripts/replay_history.py`, `scripts/run_stream.py`
- Test: `tests/unit/test_capture.py`, `tests/integration/test_streaming.py`

**Interfaces:**

- Consumes: `ree_generation.build_url`, `ree_generation.parse_payload`, `ree_generation.with_utc`, `open_meteo.build_current_url`, `features.add_renewable_share`.
- Produces:
  - `capture_once(paths, now: datetime, *, session: requests.Session) -> list[Path]`: today's REE generation into `landing/ree_generation/<YYYYMMDDTHHMMSSZ>.jsonp` and Open-Meteo current into `landing/open_meteo_current/<YYYYMMDDTHHMMSSZ>.json`; each written as a hidden `.<name>.part` file then renamed (Spark ignores files starting with `.`). An HTTP error or a payload with an empty `valoresHorariosGeneracion` list is logged as a warning and skipped; never raises.
  - `last_capture_time(landing_dir: Path) -> datetime | None`: UTC time parsed from the newest `landing/ree_generation/*Z.jsonp` file name.
  - `catch_up(paths, now: datetime, *, session: requests.Session, max_days: int = 14) -> list[Path]`: after an outage, fetches the REE file of every missing local day, oldest first, from the last capture's local date up to yesterday (today's file is left to `capture_once`), so the 2-hour watermark never discards backfilled readings. No-op when the last capture is on or after yesterday 21:00 local (today's file already covers it) or when there is no previous capture; never goes back more than `max_days` (older gaps belong to `download_history.py`). Live weather is not consumed by the stream in this phase, so its backfill (Open-Meteo `past_days`, checked on 2026-11-10: 96 hourly values for `past_days=3&forecast_days=1`) is left to phase 2.
  - `run_capture(paths, interval_seconds: int = 300) -> None`: runs `catch_up` once, then loops around `capture_once`.
  - `replay_files(files: Sequence[Path], landing_dir: Path, delay_seconds: float, *, sleep=time.sleep) -> int`: copies files in name order with the same atomic rename, sleeping between files; returns the number copied.
  - `read_generation_stream(spark, landing_dir: Path) -> DataFrame`: `readStream.text(..., wholetext=True)` with `maxFilesPerTrigger=1`, `parse_payload`, `with_utc`, `withWatermark("ts_utc", "2 hours")`, `dropDuplicatesWithinWatermark(["ts_utc"])`, `add_renewable_share`.
  - `window_metrics(readings: DataFrame, duration: str = "15 minutes") -> DataFrame[window_start, window_end, avg_demand_mw, max_demand_mw, avg_renewable_share, n_readings]`.
  - `start_stream(spark, paths, *, trigger_seconds: int = 30, available_now: bool = False) -> list[StreamingQuery]`: query `readings` (append, Parquet to `stream_output/readings`) and query `windows` (update mode, `foreachBatch` writing each batch to `stream_output/windows/batch_id=<n>`), each with its own checkpoint under `checkpoints/`.
  - CLIs: `capture_realtime.py [--interval 300]`; `replay_history.py --start 2025-01-01 --end 2025-01-07 [--delay 5]` (from `raw/ree_generation` into `landing/ree_generation`); `run_stream.py [--trigger 30] [--available-now]`.
